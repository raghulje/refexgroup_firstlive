## How Git Processes Multiple .gitignore Files

### **Git's Processing Order:**
1. **Root `.gitignore`** is processed first (applies to entire repo)
2. **Directory-specific `.gitignore`** files are processed next (applies to their directory tree)
3. **All matching patterns are combined** - if ANY .gitignore matches, the file is ignored

### **Key Principles:**
- ✅ **Hierarchical Application**: Rules cascade from root to subdirectories
- ✅ **Additive Behavior**: All matching patterns are combined (not replaced)
- ✅ **More Specific Wins**: Directory-specific rules can override or add to root rules
- ✅ **No Conflicts**: If multiple .gitignore files match the same file, it's ignored (no conflict)

## Which .gitignore File Does Git "Obey"?

### **Answer: ALL OF THEM!**

When you push code, Git checks **ALL .gitignore files** in the hierarchy:

1. **Root `.gitignore`** → Checks first for all files
2. **Server `.gitignore`** → Additional checks for `/server/` files
3. **Client `.gitignore`** → Additional checks for `/client/` files

### **Example: `/server/.env`**
```
1. Root .gitignore checks: ✅ Matches "server/.env" → IGNORE
2. Server .gitignore checks: ✅ Matches ".env" → IGNORE
3. Result: File is ignored (both rules match)
```

### **Example: `/client/node_modules/package.json`**
